# AI Coding 通用教学闭环模块开发模板（Course Module Closed-Loop Template）

> 本模板用于本仓库后续新增或迭代课程模块（对应 `src/data/courseCurriculum.ts`、`src/data/moduleTeachingPackages.ts`、`src/components/slides/common/ModuleLoopStudio.tsx` 与 `docs/knowledge-base/`）。  
> **设计原则**：不堆砌静态幻灯片，围绕「需求意图 → 人机协作 → 发现与修正 AI 缺陷 → 可验证完成标准（DoD/Rubric）→ 团队知识沉淀 → 真实项目迁移」构建完整教学闭环，并兼容双课时、短讲座、工作坊、研讨复盘与自主学习五种排课模式。

## 1. 学习目标（行为导向 · 可观察 / 可检验）

> **编写规范**：全部目标必须采用**可观察、可测试的行为动词**（例如：`能拆解`、`能配置`、`能定位`、`能拦截`、`能对比`、`能验证`、`能决策`），禁止使用含糊不可测的内隐词句；每条目标必须能在课堂或课后作业中被真实证据验证。

1. **目标 1（边界与判断）**：学员能区分 `[传统做法/边界 A]` 与 `[AI 协同边界 B]`，并在给出具体约束后做出放行或拒绝决策。
2. **目标 2（人机协作执行）**：学员能结合 `[工具/规则/模板]` 引导 AI 完成 `[具体切片任务]`，并通过 `[客观命令/测试]` 验证输出。
3. **目标 3（纠偏与知识沉淀）**：学员能识别 `[典型 AI 失败模式]`，将其修正策略或检查清单沉淀至仓库知识库。

## 2. 传统方式 vs AI Coding 对比清单 & 人机分工

### 2.1 工程流程对照表
| 对比维度 | 传统编程方式 | AI Coding 方式 | 变化与新风险 |
| :--- | :--- | :--- | :--- |
| **任务分解与意图表达** | `[开发者自行拆分文件与接口签名]` | `[人类编写 Context / Intent / Guardrails / DoD，AI 扩展细节]` | `[表达模糊会在秒级放大为多文件污染]` |
| **候选实现与执行** | `[逐行手写，边写边小步校验]` | `[AI 快速产出整片候选修改，支持局部自愈]` | `[容易顺带修改边界外文件或引入冗余依赖]` |
| **验证与排障成本** | `[作者清楚改动范围，定位直接]` | `[高度依赖独立测试、类型检查与 diff 审查]` | `[瓶颈从“打字慢”转移到“审查与边界把关”]` |
| **知识资产沉淀** | `[零散笔记或口头传帮带]` | `[规则文件 .mdc / 核查清单 / 团队工程知识库]` | `[若不定期维护版本号，过期规则会误导 AI]` |

    - `[目标优先级、切片范围与业务不变量定义]`

    - `[最终 Diff 验收、合并签署与连续失败后的回滚止损]`
  - **可交给 AI 接手或起草**：
    - `[上下文影响面初筛、候选方案对比草案、样板代码与局部修复]`
  - **人机协作闭环**：`[人定边界与契约 -> AI 出候选方案 -> 人审范围与隐患 -> AI 执行局部修正 -> 命令验真 -> 人决定保留或回退]`

## 3. 教师讲解 / 现场演示步骤（非“一次性成功”脚本）

> **演示铁律**：禁止只演“输入一句提示词 AI 一次写完美”的顺风剧。现场演示**必须**暴露一次真实 AI 缺陷或边界失控，展示人如何发现问题、补充约束、让 AI 重试并通过客观命令验收。

- **课前准备与环境要求**：`[演示所需示例分支、本地命令及离线模拟状态]`
- **预期演示目标**：`[本段 15–20 分钟演示希望学员亲眼记住的关键转折]`

### 分步现场演示脚本
1. **Step 1 · 下达常见有缺陷指令（暴露第一轮问题）**
   - **讲师动作**：`[向 AI 输入缺少关键边界或上下文噪音偏高的典型初始指令]`
   - **AI 真实表现/翻车点**：`[明确指出 AI 产出了看似能运行但越界/存在安全隐患/漏边界的结果]`
   - **人类把关点**：`[暂停采纳，指出问题所在，解释为什么不能直接点 Accept]`
2. **Step 2 · 诊断根因并补充约束重新生成**
   - **讲师动作**：`[回退或开新上下文，补充明确 Guardrails、目录范围或安全不变量]`
   - **AI 修正表现**：`[对比说明补充约束后方案收敛为可控范围]`
   - **人类把关点**：`[人工挑出剩余可选方案中的权衡点，否决过度设计部分]`
3. **Step 3 · 客观命令验真与最终拍板**
   - **讲师动作**：`[运行 npx tsc --noEmit / npm run lint / 定向 test 或 curl 反向用例]`
   - **AI 表现与证据**：`[展示命令退出码、git diff --stat 及边界用例通过结果]`
   - **人类把关点**：`[决定合并或打回，并将新暴露的边界记录为规则/检查清单]`

- **学员卡住时常见引导话术（至少 2 条）**：
  - `[引导 1：例如把大需求砍小到单入口文件，先写一条明确禁止改动清单]`
  - `[引导 2：例如连错超过 2 次先停手看 git diff，而不是继续粘贴同一段报错]`
- **无 API Key / 离线环境降级演示方案**：`[写明如何利用本地课程沙盘或静态对照代码完成同等演示]`
- **多元可接受解法说明**：`[列出除示范方案外的其他合理技术/流程解法，避免教条化唯一答案]`

## 7. 完成标准：多维评价 Rubric 与三档迁移任务

### 7.1 多维可核查 Rubric（至少 3 维，严禁用代码行数或提示词长度充当标准）
| 评价维度 | 合格通过标准（可观察证据） | 提交核验凭证 | 一票否决红线（Red Flag） |
| :--- | :--- | :--- | :--- |
| **1. 边界与范围控制** | `[明确目标与禁触碰边界，未越界改动无关代码]` | `[规格清单 + git diff --stat]` | `[出现无关全局改写或大而空的无界指令]` |
| **2. 客观验证与安全底线** | `[跑通对应真实检查命令，无明文凭证与服务端鉴权缺口]` | `[退出码为 0 的命令行输出 + 反例测试]` | `[只靠口头说“跑通了”或篡改断言凑绿灯]` |
| **3. 人工把关与资产沉淀** | `[保留人类删改与裁决依据，产物同步更新反馈记录]` | `[评审修正记录 + 更新后的知识库条目]` | `[未读内容直接全部 Accept，零经验沉淀]` |

### 7.2 课后三档迁移任务（按时间与角色按需选做）

#### 档位 A：30 分钟内快速验证任务
- **目标**：`[在手头现有 1 个小问题或历史提交上验证本模块核心动作]`
- **输入与限制**：`[限 1 个文件或单次审查，不改核心架构，禁止输入真密钥]`
- **交付物**：`[修订前后对照或半页诊断笔记]`
- **验证方法**：`[具体命令或同伴快检]`
- **知识库沉淀**：`[把发现的 1 条边界补入常用清单]`
- **无外部环境替代**：`[基于课程沙盘或本地离线小仓库完成]`
- **人工审查要点**：`[人类亲手核对是否真的消除了原返工隐患]`

#### 档位 B：数小时模块级任务
- **目标**：`[在一个真实功能切片或独立练习分支跑通完整人机协同闭环]`
- **输入与限制**：`[必须先留存规格/设计卡片再写代码，限定重试轮次上限]`
- **交付物**：`[功能提交 + 测试证据 + 本模块标准产物文档]`
- **验证方法**：`[运行完整构建/Lint/单测并构造至少 1 个失败反例]`
- **知识库沉淀**：`[更新对应 .mdc 或记录一条新的失败案例]`
- **无外部环境替代**：`[使用本地测试数据/Mock 路由闭环运行]`
- **人工审查要点**：`[逐文件审核 diff、边界校验与错误降级提示]`

#### 档位 C：多日团队或跨模块实战任务
- **目标**：`[在多人协作仓库或跨模块联动任务中落地并评测本模块工程机制]`
- **输入与限制**：`[须包含团队交叉 Review 与试点前后返工指标对比]`
- **交付物**：`[版本化的仓库规则/文档 PR + 试点效果复盘记录]`
- **验证方法**：`[由未参与编写该规则的队友按文档独立跑通一次]`
- **知识库沉淀**：`[在 docs/knowledge-base/ 提交新条目、修订假设或归档废弃做法]`
- **无外部环境替代**：`[以本地双人/团队工作坊演练和离线 PR 检查脚本替代云端自动化]`
- **人工审查要点**：`[技术负责人核查新规范是否有效降低返工且未造成过度流程摩擦]`
