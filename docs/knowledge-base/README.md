# AI Coding 团队工程知识库治理与目录规范

> 本目录是课程与真实工程团队共享的**活体工程资产库（Living Knowledge Base）**，与课程界面右侧「知识库与来源 → 团队知识库」标签页保持结构映射，避免“只写在 PPT 里、带不回仓库”的纸面规范。

---

## 1. 知识分类体系（9 类严格区分）

| 分类编码 | 中文标签 | 适用职责 | 典型存放内容 |
| :--- | :--- | :--- | :--- |
| `starter-rule` | 入门规则 | 刚建库或刚接手模块时的最小防呆边界 | `00-project-dna.mdc`、路径隔离 `globs` 规则 |
| `example` | 示例 | 可直接对照的正向代码/配置样本 | 服务端 Webhook 验签路由、契约优先接口 Diff |
| `checklist` | 检查清单 | 上线/合并/迁移前逐条打勾的客观核对项 | Rules 与 MCP 安全审计清单、Vibe 报错五步排查表 |
| `template` | 模板 | 可复制改写的提示词、Spec 与工作流骨架 | Plan→Agent 蓝图模板、ADR 决策记录模板 |
| `failure-case` | 失败案例 | 真实踩坑复盘与“看起来对但实际错”的警示 | 测试作弊（Reward Hacking）、规则冲突与上下文污染案例 |
| `adr` | 决策记录 | 关键技术选型、取舍依据与回滚条件 | 架构决策记录（ADR）、模型/数据库分层取舍 |
| `team-convention` | 团队约定 | 多人协作必须统一遵守的命名、权限与评审规则 | Issue-to-PR 异步派发约定、Worktree 目录隔离约定 |
| `hypothesis` | 待验证假设 | **尚未经过多项目长期验证**的新工具/新做法（必须标注复核日期） | 长链路 ACC 压缩阈值经验值、特定 UI 提示词微调假设 |
| `deprecated` | 已废弃实践 | **明确淘汰并禁止继续抄用**的旧做法与迁移指引 | `alwaysApply: true` 全量塞规则、以生成代码行数度量效能 |

## 2. 元数据与版本演进规范

每一条进入本知识库（及前端索引 `src/data/teamKnowledgeBase.ts`）的条目，必须完整标注：
1. **版本号（`version`）与更新日期（`updatedAt`）**：每次规则或模板修正递增语义版本（如 `v1.2`），并附变更原因。
2. **维护责任人（`owner`）**：明确谁负责响应误报、更新工具版本差异与清理过期条款（如 `架构组 / TL`、`安全与 QA 负责人`、`课程教研维护组`）。
3. **来源标注（`source`）**：区分来自外部官方文档、开源实践参考还是本团队/课堂故障复盘。
4. **适用范围（`scope`）**：明确适用于个人实验、特定目录（如 `src/server/**`）、全仓库还是企业合规项目。
5. **核验状态（`validationStatus`）**：
   - `verified`（已验证）：至少在真实工程链路或自动化测试中验证有效；
   - `hypothesis`（待验证假设）：仍在试运行观察期，使用前需小范围对照评测；
   - `deprecated`（已废弃实践）：保留原因说明与替代方案链接，防止新人误用。

## 3. 用完即改的反馈闭环（Post-Use Feedback Loop）

课程产物迁移到真实项目后，严禁“复制完就失联”。每次使用后执行四选一动作：
1. **保留（Keep）**：本轮按模板执行一次通过且无返工，记录使用日期。
2. **微调（Refine）**：若 AI 仍在同一边界犯错，把新踩出的边界条件补入 `checklist` 或 `.mdc` 规则并升小版本。
3. **升级为团队规范（Promote）**：某条 `hypothesis` 在 2 个以上迭代/PR 中持续降低返工率，经 TL 评审后转正为 `team-convention` 或 `starter-rule`。
4. **废弃归档（Deprecate）**：随 Cursor / 模型 / 框架升级失效，或发现带来负面耦合的条目，标为 `deprecated` 并填写 `migrationNotes`，严禁直接删除历史留痕（避免别人按旧记忆重写回坑）。

## 4. 个人知识与团队规范的隔离原则

- **个人偏好留本地**：个人表达习惯、临时草稿提示词、实验性调试脚本留在个人备忘或本地未提交分支。
- **团队共有进仓库**：影响安全底线（密钥、鉴权）、数据模型、CI 门禁、代码评审标准与跨人协作接口的规范，必须经过 PR Review 后提交至团队 `.cursor/rules/`、`AGENTS.md` 与 `docs/knowledge-base/`。
- **反臃肿约束**：规则文件按路径 `globs` 拆分，单文件保持精简；超过 90 天无人复核或零引用的条目触发定期清理评审。
